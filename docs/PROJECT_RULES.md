# ATLAS — обязательные правила разработки

1. **Источник истины — GitHub `Dmitrynest2012/ATLAS`, ветка `main`.** Новые версии фиксируются коммитами и попадают в локальные копии через безопасную автоматическую синхронизацию.
2. **Сохранение работоспособности.** Каждый релиз должен проходить `npm run check` и `npm run build`. Без отдельного задания не ломать существующую функциональность.
3. **Русский интерфейс и комментарии.** Названия элементов, подсказки и JSDoc — на русском. Технические идентификаторы и имена файлов допустимы на английском.
4. **Чистая структура.** Разделять разметку, стили, логику, скрипты и документацию; избегать неуправляемых глобальных переменных и скрытых сетевых обращений.
5. **Безопасность.** Запрещено коммитить реальные медицинские сведения, персональные записи, ключи API, токены и пароли; публичная демоверсия должна работать только с безопасными заглушками.
6. **Поведение элементов.** Все интерактивные кнопки должны иметь действие; незавершённые экраны явно отмечать как заготовки. Поддерживать клавиатуру, мобильные устройства и уменьшенную анимацию.
7. **Стабильные обновления.** Скрипт обновления не должен затирать локальную работу, автоматически выполнять `git reset --hard` или скрывать конфликты; применять только fast-forward чистой ветки `main`.
8. **npm и зависимости.** Вести `package-lock.json`. При обновлении манифеста безопасный синхронизатор автоматически выполняет `npm ci --ignore-scripts` и фиксирует неудачи в логе.
9. **Версии.** Использовать SemVer (`0.1.0`, `0.1.1` и т. д.); при каждом выпуске обновлять `CHANGELOG.md` и необходимые docs.
10. **Запуск и развёртывание.** Все команды и настройки автоматизации документировать. Деплой на GitHub Pages происходит через проверяющий workflow; локальная синхронизация — через Планировщик Windows.

Эти правила действуют для всего кода проекта ATLAS и пересматриваются только по отдельному согласованному решению.
