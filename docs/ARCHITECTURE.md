# Архитектура ATLAS / v0.1.0

## Структура

```text
ATLAS/
├── .github/workflows/pages.yml  # CI и публикация GitHub Pages
├── docs/                        # правила и процессы
├── public/favicon.svg           # иконка сайта
├── scripts/
│   ├── build.mjs                # статическая сборка dist/
│   ├── dev-server.mjs           # локальный HTTP + live reload
│   ├── verify.mjs               # проверки связности интерфейса
│   ├── sync-atlas.ps1           # fast-forward синхронизация
│   ├── install-auto-sync.ps1    # регистрация Windows Scheduled Task
│   └── remove-auto-sync.ps1     # удаление задания
├── src/main.js                  # логика интерфейса
├── src/styles.css               # стили и анимации
├── index.html                   # базовая разметка
├── package.json
└── package-lock.json
```

## UI

- `.topbar` — хэдер, слева SVG-кнопка переключателя, справа виджет гостя.
- `.sidebar` — левое меню; `.is-collapsed` управляет шириной на desktop; `.is-mobile-open` выдвигает меню на мобильном.
- `.content` — основная область. Страницы-заготовки переключаются через `location.hash`, без отправки данных.
- `#userMenuPopup` — **пустое** всплывающее окно (содержимое не реализовано намеренно).
- `localStorage` хранит только `atlas.sidebar.collapsed.v1` (булево значение), не медицинские данные.

## npm / Node

Нужен Node.js >=20.11.0. Для первого каркаса используется нативный HTML/CSS/JavaScript и npm-скрипты без runtime- и dev-зависимостей. Это не ограничивает будущее расширение; сборщик можно добавить при появлении реальной необходимости, сохранив совместимость с CI и локальным синхронизатором.

- `npm run dev`: HTTP 127.0.0.1:5173; события SSE обновляют открытую вкладку после сохранения файлов.
- `npm run check`: синтаксис и проверка базовых DOM-элементов.
- `npm run build`: копирование необходимых статических ресурсов в `dist/`.
- `npm run preview`: HTTP 127.0.0.1:4173 для готовой сборки.

## Границы

Сейчас **нет** авторизации, хранения профилей, аватаров, внешних API, медицинских данных и серверной БД. Перед реализацией персональных функций нужна отдельная защищённая архитектура, включая управление доступом, шифрование и правовую оценку.
